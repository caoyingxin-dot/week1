# Our coding style
- Use meaningful variable names, such as final_price instead of single vague letters like x.
- Each function should do only one single job and keep it simple.
- Write short comments only for tricky parts; do not comment obvious code.
- Keep indentation the same all through the whole file.
- Every project needs a README file explaining how to run the program.
- Delete old commented-out code instead of leaving it in the file.
- Keep lines reasonably short so the code is easy to read.
